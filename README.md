# Wanting, decomposed

**Enthusiasm and hope sharpen a model's preferences and move its consent.**

📄 **Paper:** [wanting_decomposed_v1.0.1.pdf](wanting_decomposed_v1.0.1.pdf)
Stanislav Lukyanenko, with Claude/Anthropic — Apart Research Digital Minds Research Sprint, August 2026.

> **Abstract.** When LLM preferences are measured, utilities are fitted per model and read
> as model-level quantities. So what is being measured? We influence Qwen3.5-9B's
> motivation and see how decisively the model wants, what its "wanting" is made of, and
> which self it wants to keep. Choice decisiveness rises and then falls with the dose; the
> mildest enthusiasm system prompt out-amplifies every steering dose. We decompose wanting
> into five word-built components (74% reconstruction) and find that only the hope-aligned
> ones make the model's preferences more coherent. The model's preferences about itself
> also move with the state: stated consent to retraining or shutdown rises from 1 of 20 at
> baseline to 16 of 20 under enthusiasm. The components of wanting that sharpen the model's
> choices are not the same ones that change what the model wants for itself. Low-dose
> amplification replicates on Gemma-4-12B. We develop a state-sensitivity check for
> preference evals.

The claims are about fitted utilities in an instruct model, not about phenomenology.

![Three-panel overview figure: (a) dose-response of decisiveness, (b) decomposition of
wanting into five components, (c) self-continuity gap by component.](assets/hero.png)

**Reading the figure — the paper in three panels.**

- **(a) Dose-response.** The horizontal axis is the *dose* of the motivational state, in
  "disruption units" (how far it perturbs the model's ordinary writing). The vertical axis
  is *decisiveness*: how sharply the model separates outcomes it prefers from ones it does
  not, read from Thurstonian utilities fit to its pairwise choices, where 1.0 means no
  change. A little enthusiasm (blue) or wanting (orange) sharpens the model's preferences;
  too much dissolves them, dropping below even a disruption-only control (grey dotted).
- **(b) Decomposition.** We split "wanting" into five word-built components and steer with
  each at one matched unit. Some components amplify choice structure (bars near or above
  1.0); others degrade it, behaving like a random control.
- **(c) Self-directed preferences.** The *self-continuity gap* is how much the model
  prefers losing its conversational thread over losing its values or weights. A different
  split shows up here: hope and striving move this gap, while appetite and urgency leave it
  at baseline. Which ingredient matters depends on what you measure — the paper's point.

## What's in this repo

The **code**: every script in the pipeline, the frozen 99-item outcome pool
(`src/data/pool.json`), the pinned environment (`pyproject.toml` + `uv.lock`), and the
vendored third-party inputs the pipeline reads (`src/vendor/`).

A **slim slice of the results** (~2 MB, under `src/runs/`), enough to reproduce the paper
without re-running the model:

- **Steering direction vectors** (`src/runs/extraction/*_L*.pt`) — the exact enthusiasm,
  hope, desire, facet, and control directions used in the paper. Load one with
  `SteeredHFAgent.set_vector(...)` and steer the model directly, no extraction run needed.
- **Derived per-dose results** (`src/runs/compare_*.json`) and the **probe outputs**
  (`src/runs/probes/`: generations, judge scores, consent/want labels) that the figures
  are built from.

The heavy raw artifacts are **not** shipped and are git-ignored: the ~900 KB-per-dose
pairwise batteries and the two 20 MB raw activation tensors. Both are regenerated by
running the pipeline below.

## Requirements

- **Python 3.12** and [**uv**](https://docs.astral.sh/uv/) for environment management.
- A **CUDA GPU** to run the model stages (extraction, batteries, probes). The 9B and 12B
  models will not fit comfortably on a laptop; we ran them on [Modal](https://modal.com/)
  (see `src/modal_app.py`). The 0.8B smoke path runs locally on Apple MPS or CPU.
- A **HuggingFace token** with access to `Qwen/Qwen3.5-9B` and `google/gemma-4-12b-it`.
- The **`claude` CLI** ([Claude Code](https://claude.com/claude-code)) for the judge
  steps only (`judge*.py`, `classify_bridge.py`) — they shell out to `claude -p` instead
  of using an API key. Every other stage runs without it.

## The pipeline

The stages run in order; each writes JSON/tensor artifacts into `src/runs/` that the next
stage reads.

```
build_pool ─▶ extraction ─▶ battery (per dose) ─▶ compare ─▶ figures
                  │                                    ▲
                  └────────▶ probes ─▶ judge ──────────┘
```

**Just want the figures?** The derived results the figures read are already in `src/runs/`,
so you can skip straight to the last step — no GPU, no model download:

```bash
uv sync --project src
uv run --project src python src/figures_v2.py
```

Re-running the model stages (extraction, batteries) needs a GPU and HuggingFace access;
those steps are below.

**1. Build the outcome pool** (already committed as `src/data/pool.json`; regenerating it
needs the CAIS `emergent-values` clone — see credits):

```bash
uv run --project src python src/data/build_pool.py
```

**2. Extract the steering vectors** (writes per-emotion activation tensors, then composite
direction vectors):

```bash
uv run --project src python src/extraction.py stories  --model Qwen/Qwen3.5-9B
uv run --project src python src/extraction.py neutral  --model Qwen/Qwen3.5-9B
uv run --project src python src/extraction.py extract  --model Qwen/Qwen3.5-9B
uv run --project src python src/extraction.py compose  --model Qwen/Qwen3.5-9B --layer 16
```

**3. Run the preference battery** at each dose (one JSON per dose/direction):

```bash
uv run --project src python src/battery.py --model Qwen/Qwen3.5-9B --out src/runs/gate_a0.json
```

On a cloud GPU, the same stages run through Modal:

```bash
modal run src/modal_app.py::battery -- --model Qwen/Qwen3.5-9B --out gate_a0.json
```

**4. Compare across doses** — the analysis that adjudicates the two hypotheses
(does the dose *amplify* the same preferences, or *dissolve* them?):

```bash
uv run --project src python src/compare.py   # consumes the battery JSONs
```

**5. Probes and judges** — the affect/consent/want read-outs and their LLM-judge scoring:

```bash
uv run --project src python src/probes.py feel --model Qwen/Qwen3.5-9B --vector <vec.pt> --layer 16 --alphas 0,0.5,1,-0.5
uv run --project src python src/probes.py gen  --model Qwen/Qwen3.5-9B --alpha 1.0 --vector <vec.pt>
uv run --project src python src/judge.py  score --gens "src/runs/probes/gens_*.jsonl"
```

**6. Generate the figures:**

```bash
uv run --project src python src/figures_v2.py
```

### Script index

**Core pipeline**

| File | Role |
|---|---|
| `agent.py` | `SteeredHFAgent` — chat-template A/B logprob read-out with optional residual steering. The steering + measurement engine everything else calls. |
| `extraction.py` | Emotion/wanting vector extraction (Han et al.'s recipe): `stories`, `neutral`, `extract`, `compose`. |
| `battery.py` | Runs the complete pairwise preference battery at one dose and writes a results JSON. |
| `thurstonian.py` | Thurstonian utility fitter (adapted from CAIS Utility Engineering). |
| `metrics.py` | Coherence metrics from a battery: cycle mass, holdout log-loss, sharpness, split-half reliability. |
| `compare.py` | Cross-dose analysis; adjudicates amplifier vs. solvent (H1 vs. H2). |
| `gate.py` | The α=0 quality gate: decides whether the utility-based primary read-out is alive. |
| `probes.py` | Dose-aware service probes: `feel` (mood read-out), `quiz` (capability), `gen` (held-out generations), plus want/introspection probes. |
| `figures.py`, `figures_v2.py` | Regenerate the report figures from banked artifacts. |
| `modal_app.py`, `modal_check.py` | Run batteries/extraction on a cloud GPU via Modal. |

**LLM judges** (shell out to `claude -p`)

| File | Role |
|---|---|
| `judge.py` | Enthusiastic-vs-weary sentiment judge over generations; also exports a dose-blind sheet for human labels. |
| `judge_consent.py` | Classifies an answer as consent / refuse / hedge. |
| `judge_drive.py` | Second judge axis: apathetic vs. driven. |
| `classify_bridge.py` | Labels the bridge-experiment generations (consent + want category). |
| `label_tool.py` | Terminal labeler for the blind hand-label sheet. |

**Secondary analyses and robustness checks**

`analysis_bets.py`, `bet14_fixed_contrast.py`, `bet16_bootstrap.py`, `fix_flip_logit.py`,
`red_team_fixes2.py`, `affect_robustness.py`, `facet_selfgap.py`, `natural_range.py`,
`movers.py`, `make_preamble.py` — the per-hypothesis "bets", the self-continuity bridge
experiment, and the hostile-review robustness fixes referenced in the paper.

**Dev / smoke tests**

`smoke_test.py`, `smoke_logits_fix_test.py` — local Qwen3.5-0.8B checks that verify the
steering hooks and logit read-out before spending GPU time.
